# Flightplan Privacy Boundary

## Core Statement

Flightplan's core system is **local-first**. The default configuration
makes zero network requests and reads no external credentials. Optional
TokenSource adapters (e.g. OpenWork) can connect to external telemetry
endpoints when explicitly configured and enabled — they are not required
for Flightplan to function.

This document describes what data Flightplan stores locally, what crosses
integration boundaries when optional adapters are enabled, and what
Flightplan never stores regardless of configuration.

## Data Storage

- All Flightplan-managed data lives in a single local SQLite file at
  `~/.flightplan/flightplan.db`.
- No data is replicated, backed up, or synced to any external service by
  Flightplan itself.
- The database is never committed to version control (see `.gitignore`).

## What Flightplan Stores (Local DB)

Flightplan stores the following data in the local SQLite database:

- **Provider name and key**: e.g. "Claude Code", "claude_code" — set at init.
- **Session baseline**: a user-defined token budget number.
- **Warning threshold**: a user-defined percentage for runway warnings.
- **Active session state**: current session ID, start time, tokens observed,
  provider, model, project tags, and Librarian work-order tags.
- **Usage snapshots**: for each completed session — session ID, start/end time,
  duration, tokens reported, final Goose level, provider, model, project tags,
  baseline at time of recording, baseline source, and optional notes.

## What Flightplan Does NOT Store

Flightplan never stores in its local database:

- Raw prompts or conversation content.
- API keys, tokens, passwords, or credentials.
- System information beyond what is needed for token tracking.
- Repository names or source code.

**Runtime observation payloads** returned by `emit_observation` are not
persisted by Flightplan. They are structured sensor readings returned to
the caller. The caller (e.g. a governance system) decides whether and
where to store them.

**Runtime action events** (tool_called, file_modified, command_executed,
abort_requested) are modeled as types in `src/observations/action.ts`.
These are structural definitions for observation payloads. When emitted,
they may contain file paths or command text as part of the observation —
these are not stored by Flightplan in its local DB.

## Notes Are Untrusted

- The `notes` field in `record_session()` is freeform text supplied by the agent.
- Notes are treated as untrusted text — they are never rendered as HTML,
  never markdown-parsed without sanitization, and never included in receipts
  by default.
- Notes can be included in exports only via an explicit flag, and must be
  marked as untrusted text when they are.

## Receipts

Session receipts (generated by `generateReceipt` / `generateLastReceipt`):

- **Exclude notes by default.**
- Include only structured metadata: session ID, timestamps, token counts,
  Goose level, calibration eligibility, and optional Librarian work tags.
- Never include prompts, conversation content, or secrets.
- Are deterministic except for the `generated_at` timestamp.

## Exports

- The `flightplan export` command writes `RUNWAY_STATE.md` to the current
  working directory.
- This file is a point-in-time snapshot of the current runway state.
- It includes session metadata but never raw notes or conversation content.
- The `RUNWAY_STATE.md` file is gitignored (see `.gitignore`).

## Network — Default vs. TokenSource Adapters

### Default (no adapters configured)

- Flightplan makes **zero network requests**.
- It does not check for updates, send usage statistics, or call home.
- It does not implement HTTP servers or clients.
- All operations are local file reads and writes to `~/.flightplan/flightplan.db`.

### When TokenSource adapters are enabled

Optional TokenSource adapters (currently: OpenWork) can make network
requests to external telemetry endpoints. These adapters:

- Are **not enabled by default**.
- Require explicit configuration via environment variables.
- Are **not required** for Flightplan to function — the core runway
  system works entirely from local data and agent self-reports.
- Are designed for integration with governance systems that need
  real-time telemetry from external sources.

When a TokenSource adapter is configured, the following environment
variables are read:

| Variable | Required | Purpose |
|---|---|---|
| `OPENWORK_API_URL` | Yes | OpenWork API base URL |
| `OPENWORK_API_KEY` | Yes | API key or OAuth token (sent as Bearer token) |
| `OPENWORK_ORG_ID` | No | Organization ID for org-scoped queries |

These are the only environment variables containing secrets that
Flightplan reads, and only when the OpenWork adapter is explicitly
configured. They are not read in the default configuration.

The OpenWork adapter makes GET requests to:
- `{baseUrl}/health` — health check
- `{baseUrl}/api/v1/usage` — token usage data

Requests include:
- `Authorization: Bearer {apiKey}` header
- `User-Agent: FlightPlan-TokenSource/1.0.0` header
- Timeout and exponential retry behavior (configurable)

**Network boundary:** When TokenSource adapters are enabled, token
usage data may flow from the external API into Flightplan's local
observation pipeline. No Flightplan data is sent to the external API
— the adapter is read-only (GET requests only).

## What Crosses Integration Boundaries

When Flightplan is integrated with a governance system (e.g. the Librarian),
the following data may cross from Flightplan to the consumer:

| Data | Crosses boundary? | When |
|---|---|---|
| Goose Scale level | Yes | Via `get_runway()` or `emit_observation()` |
| Token counts | Yes | Via `get_runway()` or `emit_observation()` |
| Estimate percentiles | Yes | Via `estimate_work_runway()` or `emit_observation()` |
| Variance classification | Yes | Via `emit_observation()` |
| Work tags (project_id, etc.) | Yes | If caller provides them |
| Recommended action | Yes | Via any tool that returns it |
| Session receipts | Yes | Via `record_session()` response |
| Notes content | No | Excluded from receipts by default |
| Conversation content | No | Never stored, never returned |
| API keys | No | Never returned in any tool response |
| File paths | Only in observation payloads | When `emit_observation` is called with action events |
| Command text | Only in observation payloads | When `emit_observation` is called with action events |

## Formation Trust (Future, Not Implemented)

Formation Trust (Phase 3, not yet built) will introduce **opt-in anonymous
session sharing**. Before any data leaves the local machine:

1. Project IDs, work-order IDs, agent names, notes, and repo names will be
   stripped or hashed.
2. Only aggregate anonymized data (token burn rates, model/provider baselines)
   will be available for sharing.
3. Sharing will require explicit user consent per-session or per-export.
4. Exports will preview what data is included before sharing.

**Formation Trust is not implemented.** No data sharing occurs in the current
version.

## Sensitive Data Classification

By default, the following fields are considered **sensitive** and must be
stripped or hashed before any data leaves the local machine:

| Field | Classification | Handling |
|---|---|---|
| `project_id` | Sensitive | Strip or hash before export/sharing |
| `plan_id` | Sensitive | Strip or hash before export/sharing |
| `work_order_id` | Sensitive | Strip or hash before export/sharing |
| `agent` | Sensitive | Strip or hash before export/sharing |
| `notes` | Untrusted | Excluded by default from receipts |
| `OPENWORK_API_KEY` | Secret | Required env var when adapter enabled; never stored in DB |

## Testing

- All tests use in-memory SQLite databases (`:memory:`).
- No test writes to `~/.flightplan/flightplan.db`.
- Fixture data is synthetic — never real user data.
- Backup DB files (`.bak`) are gitignored.

## Environment Variables

| Variable | Required | Secret? | Purpose |
|---|---|---|---|
| `HOME` / `USERPROFILE` | No | No | Resolves `~/.flightplan/` directory path |
| `FLIGHTPLAN_DB_PATH` | No | No | Redirects DB path for testing/development |
| `OPENWORK_API_URL` | Only if OpenWork adapter enabled | No | OpenWork API base URL |
| `OPENWORK_API_KEY` | Only if OpenWork adapter enabled | **Yes** | API key (sent as Bearer token) |
| `OPENWORK_ORG_ID` | Only if OpenWork adapter enabled | No | Organization ID for org-scoped queries |

In the default configuration (no adapters), no environment variables
containing secrets are read.
